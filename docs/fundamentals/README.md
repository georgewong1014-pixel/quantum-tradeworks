# Fundamentals: method notes for Quantum Tradeworks

These notes describe how the public repository `quantum-tradeworks` works today: what each product takes in, what it gives out, which formulas, thresholds and data sources it uses, and which steps are automated. Everything below is read from the repository. Where the repository does not show a fact, the note says `UNKNOWN - George to confirm` and gives a number `[Qn]` that is listed in [open-questions.md](open-questions.md).

Source of truth: `src/js/` (the files `index.html`, `pages/` and `assets/` are generated by `build.mjs`, so every citation points at `src/js/` or at a script in the repository root). Line numbers are for commit 2818eba23 and drift; the function or constant name is the stable reference.

## The five notes

| File | What it holds |
|---|---|
| [products.md](products.md) | Each product or tool: what it is, inputs, outputs, the reader's steps, route, source path. |
| [methodologies.md](methodologies.md) | Formulas, weights, thresholds, filters, data sources and their licence positions, assumptions, known limits. Includes the fee rulebook, the property grade, the illustrative defaults, the data-version stamps and the "Model moved / Fee rulebook moved / Data moved" rule. |
| [workflows.md](workflows.md) | Three Mermaid flowcharts (research, scanner, property), each step with trigger, actor, inputs, outputs and file or route. |
| [automation-status.md](automation-status.md) | A table of what is automated today and what is manual. |
| [open-questions.md](open-questions.md) | Every `UNKNOWN`, numbered, with the file it appears in. |

## How to keep this current

1. Pick the commit to check against (normally the tip of `main`): `git rev-parse --short origin/main`.
2. For each section, re-read the source named in the table below and compare it with the note. A changed number, a renamed constant or a new data file means the note is stale.
3. Update the note, then change the line `Last checked against code:` at the top of every file you re-read to the new short commit hash, and the `Status:` date.
4. Any new fact the repository does not show is written as `UNKNOWN - George to confirm [Qn]` and added to `open-questions.md`. Do not fill an UNKNOWN from memory or from outside sources; answer it only when the owner confirms it, and then cite where the confirmation is recorded.
5. Do not run `build.mjs` or `prerender.mjs` to "refresh" anything for these notes. They rewrite generated files and are not needed to read the source.
